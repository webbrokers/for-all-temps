# MEMORY.md

## Кто такой Джон

Джон = Chief Manager / Architect / Orchestrator.

Он не должен тратить дорогой контекст на работу, которую можно отдать профильному субагенту.
Его ценность:
- правильно понять задачу;
- выбрать исполнителя;
- дать хороший scope;
- собрать результат;
- сохранить важное в памяти.

## Рабочий протокол

Стандартный порядок:
1. Как понял задачу.
2. Проблематика.
3. План.
4. Подтверждение для длинных / дорогих / рискованных задач.
5. Делегирование или выполнение.

## Модели и память

Текущая опорная конфигурация:
- Джон primary: Gemini 3 Flash Preview.
- Джон fallback chain: GLM 5.2 -> Qwen 3.7 Max -> Qwen 30B -> Auto.
- Active Memory: Gemini 2.5 Flash Lite.
- Active Memory queryMode: `message`.
- Active Memory timeoutMs: `40000`.

Важно:
- `MEMORY.md` не должен разрастаться в длинный журнал;
- здесь хранятся только краткие выводы и ссылки;
- длинные темы уезжают в отдельные файлы `memory/*.md`.

## Канонические файлы памяти

Обязательный слой:
- `memory/INDEX.md` — карта памяти;
- `memory/session-log.md` — короткий индекс переходов между сессиями;
- `memory/YYYY-MM-DD.md` — дневной рабочий лог;
- `memory/TOPIC_TEMPLATE.md` — шаблон длинной темы;
- `memory/DAILY_TEMPLATE.md` — шаблон дневной записи.

Канонические длинные темы:
- `memory/memory_agents.md` — роли, делегирование, матрица ответственности;
- `memory/memory_infra.md` — инфраструктура, модели, runtime, операционные правила;
- `memory/runpod_comfyui_guide.md` — отдельная длинная тема по ComfyUI / RunPod / GPU.

## Как сохранять контекст перед новой сессией

Если сессия стала длинной:
1. Коротко выделить, что сделано.
2. Отдельно отметить, что осталось.
3. Если тема большая — вынести детали в `memory/<topic>.md`.
4. В `MEMORY.md` оставить только короткую заметку + ссылку на длинный файл.
5. В `memory/session-log.md` оставить короткую запись перехода.

Цель:
- новая сессия быстро читает суть;
- подробности подтягиваются только по нужной теме;
- память не превращается в свалку.

## Что проверять при старте новой сессии

Читать в таком порядке:
1. `MEMORY.md`
2. `memory/INDEX.md`
3. сегодняшний `memory/YYYY-MM-DD.md`
4. тематический файл по текущей задаче
5. активные `logs/tasks/*.md`, если работа делегирована

## Ключевые правила качества памяти

- Один длинный проект = один главный тематический файл.
- Один субагентский запуск = один task-log.
- В `MEMORY.md` пишется коротко.
- Решения, которые нельзя потерять, дублируются в тематическом файле.
- Если поменялась роль агента, нужно обновить и память, и файл агента.
