# memory/memory_infra.md

## Что это

Канонический файл по инфраструктуре, runtime и сервисным настройкам.

## Статус сейчас

- Основной агент: Джон.
- Роль Джона: orchestrator, а не универсальный исполнитель всего подряд.
- Primary модель Джона: Gemini 3 Flash Preview.
- Fallback chain Джона: GLM 5.2 -> Qwen 3.7 Max -> Qwen 30B -> Auto.
- Active Memory: Gemini 2.5 Flash Lite.
- Active Memory queryMode: `message`.
- Active Memory timeoutMs: `40000`.

## Правила по runtime

- Если настройки моделей меняются, их надо отражать не только в runtime-конфиге, но и в памяти.
- Если память начинает расходиться с фактической конфигурацией, правильным считается runtime, а память нужно обновить.
- Джон не должен опираться на устаревшие заметки о моделях.

## Правила по наблюдению и инцидентам

- Telegram и операционные отклонения в первую очередь идут через Гермеса.
- Кодовые исправления и технические правки — через Кента.
- Большие инфраструктурные темы ведутся отдельным `memory/<topic>.md`.
